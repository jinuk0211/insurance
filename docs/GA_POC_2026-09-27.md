## 공식 PDF 무결성 재검증

2026-09-27에 공식 약관 URL 52개를 다시 내려받아 분석 당시 SHA-256과 전부 대조했다. 52/52건의 해시가 일치했고, 길이가 기록된 51/51건도 바이트 수가 일치했다. DB손해보험과 현대해상 새 약관 각 1건도 별도로 원문 해시와 바이트 수를 대조했다. KDB생명 신규 PDF 2개도 별도로 원문 해시·바이트 수·페이지 수를 대조했다. 동일한 파일을 제공하는 상품 유형은 해시가 같아 현재 고유 PDF는 52개다. 자료실의 60개 문서에 원문 해시와 추출 쪽수를 고정했고, 사이트의 PDF 제공 경로는 매번 받은 전체 파일의 해시를 확인한 후 표시한다. 해시가 없는 문서는 503, 파일이 바뀐 문서는 502로 중단한다. 뷰어의 다운로드 버튼도 해시를 검증하는 사이트 경로를 사용한다. 새 원문이 나오면 설계사가 변경 내용을 검토하고 텍스트·인용 쪽을 다시 추출한 뒤 해시를 갱신해야 한다.

## 가상 가입증빙과 공식 PDF 대조 연습

문서보완 탭의 별도 연습 건 GA-EXERCISE-001은 가입 사실을 꾸민 합성 증빙이다. KB손해보험 공식 25290_1_1.pdf(2026.07 버전)의 보험사, 정확한 상품·종형, 문서 ID, 공시 버전 키, 고정 SHA-256, 암진단비 제1조 제2항의 PDF 118쪽 인용 문구를 각각 대조한다. 여섯 항목이 모두 맞아야 화면에 ‘시연 자료 일치’를 표시한다. 버전 불일치 버튼을 누르면 ‘검토 대기’가 되고 원문 연결 버튼이 사라진다. 원문을 열 때에는 프록시가 받은 PDF 해시를 다시 확인한다.

이 연습은 실제 고객의 보험증권이나 가입 특약을 확인한 사례가 아니다. 따라서 상담 보고서의 ‘검증된 약관 근거’는 여전히 0건이며 합성 시연 승인도 잠겨 있다. 실제 계약 연결에는 증권·특약·개정본을 사람 또는 승인된 연동 경로로 확인하고 그 결과를 계약별로 기록해야 한다.

## 시연 동선과 합격 기준

1. /insurance에서 합성 계약 상태, 수집 누락, 예비 보장 신호를 본다. 상품명 신호를 실제 가입 담보로 확정하지 않는다.
2. /insurance/terms에서 기존 분석 항목 필터의 ‘원문 체크포인트’를 선택해 원문 대조가 있는 약관을 찾는다. 공식 문서의 적용일과 수집 당시 판매 상태를 확인하고, 면책·감액·대기기간 후보 문구를 찾는다.
3. 후보 문구의 PDF 쪽수 링크로 해당 문서의 페이지를 열어 TXT와 대조한다. 목록에 없는 문서 요청은 404를 반환한다.
4. 비교 표는 원문 검토 체크포인트가 있는 한화생명·KB손해보험·DB손해보험 약관 각 1건을 기본 선택한다. 검토된 문서에는 체크포인트·확인할 사항·PDF 쪽수 링크를 함께 표시하고, 검토되지 않은 문서는 그 상태를 분명히 표시한다. 좁은 화면에서는 항목명 열을 고정한 채 표를 좌우로 스크롤한다. 같은 PDF를 공유하는 상품 유형을 함께 선택하면 중복 원문 안내가 나온다. 보험료·수수료·실제 가입조건이 없어 판매용 비교설명서로 출력하지 않는다.
5. /insurance의 수집·검증 → 문서보완에서 가상 증빙과 KB 공식 PDF의 여섯 항목을 확인한다. ‘개정본 불일치 시험’으로 검토 대기 전환을 확인하고 다시 복원한다.

시연 합격 기준은 이 동선을 설계사가 끊김 없이 수행하고, 원문 페이지 오류·잘못된 인용·합성 데이터 오인이 없는 것이다. 자료실의 60개 약관 항목은 원문 SHA-256 대조를 통과한 뒤 표시한다. 로컬 프로덕션 서버에서 한화 PDF 3,661,413바이트와 KB PDF 13,182,991바이트를 전체 수신해 저장된 해시와 일치함을 확인했다. 삼성화재 PDF도 2,519,879바이트를 전체 수신해 저장된 해시와 일치함을 확인했다. DB손해보험 PDF는 로컬 운영 서버의 프록시에서 4,382,829바이트를 전체 수신해 고정 해시와 일치함을 확인했고, 약관 목록·DB 뷰어는 200, 실데이터 API는 503을 반환했다. 현대해상 PDF도 로컬 운영 프록시에서 4,554,531바이트를 전체 수신해 고정 SHA-256과 일치함을 확인했다. 자료실에는 현대해상 상품의 현재 판매 상태를 미확인으로 표시하고, 실데이터 이력 API는 503을 반환했다. KDB생명 PDF 두 종도 로컬 운영 프록시에서 6,658,723바이트·6,741,745바이트를 전체 수신했고 각각의 고정 SHA-256과 일치했다. KDB 뷰어 두 경로는 200을 반환했다. NH농협생명 PDF도 로컬 운영 프록시에서 13,235,671바이트를 전체 수신해 고정 SHA-256과 일치했고, 약관 목록·NH 뷰어는 200, 실데이터 이력 API는 503을 반환했다. NH농협생명 일반 실손 PDF도 로컬 운영 프록시에서 9,729,509바이트를 전체 수신해 고정 SHA-256과 일치했고, 목록·실손 뷰어는 200, 실데이터 이력 API는 503을 반환했다.

## 배포 접근 경계

배포된 /api/insurance 및 /api/codef-datasets 경로는 CODEF 자격증명이나 과거 미리보기 암호가 설정되어 있어도 503으로 닫는다. 공개 /insurance는 합성 시연만 제공한다. 로컬 개발에서 명시적으로 시험할 때만 실데이터 API를 열 수 있으며, 이 경우에도 개발자 통제 환경을 벗어난 사용을 허용하지 않는다. 전화번호·생년월일만으로 저장 이력 또는 CODEF 세션에 접근하는 기존 흐름은 GA 설계사 인증과 고객별 접근 권한 검증을 구현하기 전까지 배포에서 사용하지 않는다.

## 배포 보안 확인 (2026-09-27)

공개 시연의 실데이터 API는 계속 503으로 차단한다. 예약 약관 수집 API는 CRON_SECRET의 Bearer 인증이 없으면 401을 반환한다. Vercel Cron User-Agent만으로는 인증하지 않는다. 운영 프로젝트에는 CRON_SECRET 환경변수 이름이 설정돼 있음을 확인했으며 비밀값은 조회하지 않았다. 헬스 응답은 서비스 상태만 반환한다. 배포된 /insurance 합성 시연에 들어오면 과거 버전에서 남긴 브라우저 고객 프로필을 삭제한다. 대시보드의 가상 분석 문구와 자료실의 실제 공식 PDF를 화면에서 구분한다.

Next.js를 16.3.6으로 올리고 undici 7.29.0, baseline-browser-mapping 2.11.26을 고정했다. 운영 의존성 pnpm audit --prod 결과는 0건이다. 전체 테스트 120개와 운영 빌드가 통과했고, 로컬 운영 모드에서 시연·약관·연금 화면은 200, 위조 Cron 요청은 401, 실데이터 이력 API는 503을 확인했다. 보안 근거: [Next.js 공식 권고](https://github.com/vercel/next.js/security/advisories/GHSA-vcvr-r3jv-pc5j), [Vercel Cron 인증 문서](https://vercel.com/docs/cron-jobs/manage-cron-jobs).

| 운영 | 공식 문서 수집 권한·갱신 주기, 장애 모니터링, 접근·보관·삭제 정책, GA 담당자 시나리오 검수 |

상담 보고서의 승인 조건에는 가입 계약과 공식 PDF 개정본을 검증한 약관 근거만 센다. 현재 계약 분석 경로에는 그 검증 연결이 없어 근거 수는 0건이다. 문서명과 연결 상태만 같은 가상 약관은 검증 근거로 집계하지 않으며 합성 시연에서는 승인 버튼을 잠근다. 체크리스트 선택은 화면상의 검토 표시이며 증권·원문 대조 기록을 대신하지 않는다. 로컬 자동 추출 문구는 별도 후보로 남아 있으며, 원본 PDF와 계약 버전 연결 전에는 승인 근거가 될 수 없다.

현 단계는 위 조건을 충족했다고 주장하지 않는다. 브라우저 저장 정보와 전화번호·생년월일 파생 키는 GA 사용자 인증 수단이 아니다. 52개 고유 PDF를 추가 LLM으로 재분석하기 전에는 문서 버전 연결과 설계사 검수 기준부터 확정한다.
